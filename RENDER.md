# Deploying TASKFLEX on Render

The repository ships a Render Blueprint (`render.yaml`) that creates four resources:

| Resource | Name | Kind | Purpose |
| --- | --- | --- | --- |
| `taskflex-db` | Postgres 16 | Database | Application data |
| `taskflex-redis` | Key Value | Redis-compatible | Dispatch, tracking, rate limits |
| `taskflex-api` | Docker (`backend/`) | Web service | FastAPI API + WebSockets |
| `taskflex-web` | Docker (`frontend/`) | Web service | React build served by nginx, proxies `/api`, `/ws`, `/uploads` |

The frontend and API share one public origin (`taskflex-web.onrender.com`), so the
browser needs no CORS configuration and WebSockets stay first-party.

## 1. Push the repository

Already done if you cloned this from GitHub. The Blueprint deploys the `main` branch.

## 2. Create the stack

Open:

```
https://render.com/deploy?repo=https://github.com/gundappagolakash18-ui/Taskflex
```

or in the Render dashboard: **New -> Blueprint -> connect the repository -> Apply**.

Sign in with GitHub and grant Render access to the repository.

## 3. Enter the secrets Render prompts for

These are marked `sync: false` in `render.yaml` and are stored only in Render:

| Variable | Value |
| --- | --- |
| `SENDGRID_API_KEY` | SendGrid API key — the production sender (see below) |
| `EMAIL_FROM` | Address shown as the sender (must be a verified SendGrid sender) |
| `SMTP_USER` | Gmail address — only used when `EMAIL_PROVIDER=smtp` (local dev) |
| `SMTP_PASSWORD` | Gmail **App Password** (16 characters, not the account password) |

> **Email on the free plan:** Render blocks outbound SMTP ports (25/465/587) on free
> web services, so Gmail SMTP cannot send from a free instance regardless of
> credentials. The blueprint therefore sets `EMAIL_PROVIDER=sendgrid`, which sends
> over HTTPS port 443. To activate it (about 5 minutes, no credit card):
>
> 1. Sign up at [sendgrid.com](https://sendgrid.com) with your Google account (free tier: 100 emails/day).
> 2. **Settings → Sender Authentication → Verify a Single Sender**: enter the Gmail
>    address you want emails to come from and click the confirmation link SendGrid
>    emails you.
> 3. **Settings → API Keys → Create API Key** (full access), copy it.
> 4. In the Render dashboard, open `taskflex-api` → Environment: paste the key into
>    `SENDGRID_API_KEY` and the verified address into `EMAIL_FROM`, then **Save**
>    (triggers a redeploy).
>
> Registration OTP emails then work on the live site. For local development,
> keep using `EMAIL_PROVIDER=smtp` with the Gmail app password in `backend/.env`.
| `RAZORPAY_KEY_ID` | Razorpay key id (test or live) |
| `RAZORPAY_KEY_SECRET` | Razorpay key secret |
| `RAZORPAY_WEBHOOK_SECRET` | Secret you set on the Razorpay webhook |
| `GOOGLE_CLIENT_ID` | Optional; leave blank to hide Google sign-in |
| `OPENAI_API_KEY` | Optional; the parser uses heuristics while `AI_PROVIDER=mock` |

JWT secrets and the OTP pepper are generated by Render (`generateValue: true`).
Never put real secrets in `render.yaml` or `.env.example`.

## 4. First boot

On the first deploy the container runs `alembic upgrade head`, then seeds reference
data. In production only the operator account and the skill catalogue are created —
the demo customers/workers/tasks (password `Demo@1234`) are **not** seeded.

Admin account:

- Email: `admin@taskflex.dev`
- Password: `akash@#123`
- Name: `akash g`

Use the same credentials as your local database. Change the password from the
admin panel if the site will be shared with other people.

URLs (assuming the names were free):

- Web: `https://taskflex-web.onrender.com`
- API: `https://taskflex-api.onrender.com`
- API health: `https://taskflex-api.onrender.com/health`

If Render assigns a different hostname (name already taken), update
`FRONTEND_ORIGIN`, `CORS_ORIGINS`, and the Razorpay/Google URLs below to match.

## 5. Post-deploy configuration

1. **Razorpay webhook** — Dashboard -> Settings -> Webhooks:
   - URL: `https://taskflex-api.onrender.com/api/v1/payments/webhook/razorpay`
   - Events: `payment.authorized`, `payment.captured`, `payment.failed`,
     `payment.refunded`
   - Put the same secret in the `RAZORPAY_WEBHOOK_SECRET` env var.
2. **Google sign-in** (optional) — Google Cloud Console -> OAuth client:
   - Authorized JavaScript origin: `https://taskflex-web.onrender.com`
3. **Share links** — live-tracking share links use `FRONTEND_ORIGIN`; keep it equal
   to the public web URL.

## 6. Verify

```bash
curl https://taskflex-api.onrender.com/health
# {"success":true,"data":{"status":"ok","app":"TASKFLEX"}}
```

Then open the web URL, sign in as the admin, and check that the dashboard loads,
the worker online toggle works, and a task can be created.

## Free-plan limits (read before sharing the link)

- Free web services **sleep after 15 minutes** without traffic. The next request
  cold-starts in roughly 30-60 seconds and open WebSockets drop while asleep.
- Free Postgres databases **expire 30 days after creation** (14-day grace period
  to upgrade). Upgrade the database before then or the data becomes inaccessible.
- Free Key Value instances have a 25 MB limit.
- **Uploads are ephemeral.** Worker ID documents, proof photos, and expense
  receipts live in `/app/uploads`, which is wiped on every deploy/restart. To keep
  them, upgrade the API to a paid instance and add a disk mounted at `/app/uploads`.
- Free instances are single-instance, which matches the app's in-process dispatch
  watchdog. If you scale to multiple instances, keep Redis enabled (it is).

## Alternative: manual services

If you prefer creating resources by hand, create the same four resources with
these settings:

- API: Docker, root directory `backend`, Dockerfile `backend/Dockerfile`,
  health check `/health`, env vars as in `render.yaml`.
- Web: Docker, root directory `frontend`, Dockerfile `frontend/Dockerfile`,
  health check `/`, env `BACKEND_URL` = `https://<api-service>.onrender.com`.
  nginx resolves this per request. Pointing it at the public API URL (rather
  than the internal host) is deliberate: it stops nginx from failing to start
  before Render's DNS is ready, and requests through Render's edge wake a
  spun-down free API instance. Internally, `http://backend:8000` is the default
  for docker compose.
- Database and Key Value: inject their connection strings as `DATABASE_URL` and
  `REDIS_URL`.

For a VPS/Docker deployment instead, see [DEPLOY.md](DEPLOY.md).
